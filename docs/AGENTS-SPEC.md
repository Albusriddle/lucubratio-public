# 智能体作业规范（Agents Spec）

> 本文件规定**这批课件内容是怎么被生产出来的**：谁做、怎么做、谁验收、什么算合格。
> 目标：把一门课的课件变成**可离线阅读、可自评、可复习、事实可追溯**的 App 内容。
> （课程规模随仓库而定：公开仓库只有 2 页自写示例；私有仓库才是完整的个人课程。）

---

> **阅读顺序**：仓库根目录的 [`AGENTS.md`](../AGENTS.md) 是硬约束（红线/约定），先读它；
> 本文件讲角色分工、逐页模板与复核流程；可复制的提示词在 [`skill/prompts.md`](skill/prompts.md)。

## 0. 铁律

1. **只依据课件**：任何结论都必须能在课件原文里找到出处，交付时标注页码（`p12`）。课件没讲的，最多写一句"（课件未涉及）"，**不许自己发挥**。
2. **不偷懒、不压缩**：要求逐页分析就必须逐页；过渡页可写得短，但**不能跳过**。
3. **两人独立产出 + 第三人复核**：同一份内容至少由两个智能体各自独立完成，再由第三个智能体比对、挑错、定稿。**单一来源的内容一律不采信**。
4. **形式服从 App**：一切产物必须符合 `docs/CONTENT-SPEC.md`（Mermaid、公式、表格、自评单元规则）。
5. **课程包禁止上传 GitHub（红线）**：`.lcr` 课程包、以及从中解出的正文页/图片/学案，**一律不得**
   提交进 git、上传到 Releases、附加到 issue/PR、或推送到任何远程。课程内容含第三方课件衍生内容，
   只保留在本地工作区（`.work/`、`content/os/` 的临时产物）与用户指定位置。
   仓库里只允许存在**自写的示例页**（`01_demo_*`、`02_demo_*`）。
   机械校验：`node scripts/verify.mjs` 会检查仓库是否跟踪了 `.lcr`/课程页，命中即失败。

## 1. 角色

| 角色 | 职责 | 产出 |
|---|---|---|
| **Lead（我）** | 拆任务、给上下文、合并、跑构建/校验、对用户交付 | 最终 HTML、构建日志、验收报告 |
| **Producer A** | 按模板独立写一份 | `draft/A/<deck>_<页段>.md` |
| **Producer B** | 拿到**同样的输入**、独立写一份（不参考 A） | `draft/B/<deck>_<页段>.md` |
| **Reviewer** | 逐段比对 A/B + 回查课件，出"差异清单 + 采信建议" | `review/<deck>_<页段>.md` |
| **Verifier（可选）** | 只做机器能查的：结构、id 唯一、公式、盒线字符、断链 | 构建/校验日志 |

> 为什么不用"1 人写 + 1 人校"：单人对课件的理解偏差会被校对者沿用；
> 双盲独立产出能暴露"两人理解不一致"的地方，而**不一致处往往就是最容易考/最容易错的地方**。

## 2. 任务拆分

- 以**课件为单位**（9 个），每个课件再按 **10–15 页**切成段，一段一个任务。
- 每个任务输入固定为：该段的逐页文本（`course/raw/<deck>.md` 的对应片段）+ 该段页码区间 + 本规范摘要。
- 单个任务产出上限约 3–5KB（太长会牺牲精度）；超出就再切。

---

## 3. 单页模板（Producer 必须逐页照写）

```markdown
### p12 · 「进程状态机」（原页标题）
**课件原文要点**
- （照抄/压缩课件里的 bullet，不改语义）

**把它讲成人话（0 基础版）**
- 一句话结论：……
- 打个比方：……（生活类比，帮助建立直觉）
- 为什么需要它：……（不这么做会出什么问题）
- 和上一页的关系：……（承上启下）

**易错点**
- ◆坑：……

**图示（可选）**
- 需要画图的，给出 Mermaid 源码（flowchart/stateDiagram），节点 ≤ 12

**课上原话/可疑处（可选）**
- 课件此处表述含糊 → 标注"待确认"，不要自行补全
```

> 讲解要求：「把我当傻子」= 不假设读者知道任何前置概念；每个术语第一次出现必须解释；
> 每段不超过 6 行（手机屏幕）；**禁止**"显然/众所周知/不难看出"这类词。

## 4. 每课件收尾（每个 deck 一份）

1. **考点清单**：分「核心考点（闭眼要会）」「一般考点」「易错点」三档，每条标注页码。
2. **随堂检测**：8–12 题，题型覆盖 选择/填空/简答；**每题必须有详细题解**（为什么对、其他选项为什么错）。
3. **一页速记卡**：全部公式 + 关键数字 + 判定规则，做成表格。
4. **自评单元**：按 `CONTENT-SPEC §5` 的规则落地（每题的标题能被规则命中）。

## 5. 复核流程（质量门）

> **2026-11 更新**：复核的产出物从"差异清单 + 采信建议"升级为**可直接执行的 PATCH 清单**，
> 否则合稿只能靠人逐条猜改（实测一轮 29 处手改）。详细模板见 [`skill/prompts.md`](skill/prompts.md)，
> 合稿分工见 [`skill/merge-playbook.md`](skill/merge-playbook.md)。

### 5.1 Reviewer 必须先做的两件事

1. **回查原页**：每个事实性论断都要能指到 `p<页码>`；指不到页码的一律标「无来源」。
2. **含图页必须重渲染核对**（`≥150 dpi`）：文字层为空、文字极少、或文字与上下文矛盾时，
   只读 `pages/*.md` 会漏掉图里的关键信息（实测：某页图上只有 4 条映射箭头，B 稿写成 6 条，
   并据此推出"10 个无效条目"，还画进了流程图——只读文本层的复核发现不了）。

### 5.2 输出格式：PATCH 清单（必须可执行）

```markdown
## 六、合稿补丁
PATCH 1
文件：A 或 B
原文：<20 字以上，能唯一定位>
改为：<完整替换文本>
理由：<对应第几条>

IMPORT 2
文件：A
取：<h3 id="检测 5">          ← 源文件里块的起点（含）
到：<h3 id="检测 6">          ← 结束标记（不含，可省）
替换：<h3 id="检测 5">         ← 目标文件里要被替换的块起点
```

Lead 用 `node tools/apply-patches.mjs <review.md> <目标片段> --as A|B [--other <源文件>]` 机械执行：
每条要求「原文」在目标文件里**恰好出现一次**；任一条失败则**整批不写入**。

### 5.3 判定标准

| 维度 | 要求 |
|---|---|
| 事实一致性 | 能在课件对应页找到依据；数字、术语、因果方向一字不差 |
| 完整性 | 覆盖该页所有 bullet，包括"坑"与"前提" |
| 编造 | 课件没有的内容**整段删**，不保留"合理推测" |
| 检测题 | 四选项错因各不相同；解析必须标页码；答案唯一 |

### 5.4 给 Reviewer 的线索必须先自验

Lead 转给 Reviewer 的任何"已知线索"（数字、页码、图内信息）**必须自己先回原文核实**；
核实不了就不给，或明确标注「来自 producer 自述，未验证」。
（实测教训：曾把 producer 自述的「15KB→3 页框」当锚点转过去，课件里根本没有这个对应。）

### 5.5 配额

| 课件页数 | 分段 | 每段题量 | 全页上限 |
|---|---|---|---|
| ≤20 | 1 | 5–8 | 8 |
| 20–60 | 2 | 3–5 | 10 |
| 60–200 | 3–6 | 3–4 | 12 |

单段达标不等于全页达标——`tools/merge-pages.mjs` 会再查一次全页上限。

## 7. 验收（Lead 每次合稿必跑）

```bash
node scripts/build.mjs     # 公式数/mermaid 数/纯文本块数是否合理
node scripts/verify.mjs    # 必须全绿（盒线字符为 0、公式基线、id 唯一…）
npm test
```

外加**人工抽检**：随机 3 页，与课件 PDF 逐条对照（我或 Reviewer 做，并在交付里写明抽检页码）。

---

## 8. 禁止事项

- 编造课件没有的定义、数字、例子
- 用"大约/可能"掩盖不确定；不确定就标"待确认"并给页码
- 把课件图用字符画重画（必须 Mermaid）
- 为了凑字数重复同一句话
- 单份稿直接定稿（跳过双人复核）
- **把课程包或课程内容上传到 GitHub**（`.lcr`、正文页、图片、打包产物）——这是红线，不是建议
- 把「解析」写进题干或选项、或用 `<details>` 自造折叠（查看器已默认折叠解析）
