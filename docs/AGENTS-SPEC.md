# 智能体作业规范（Agents Spec）

> 本文件规定**这批课件内容是怎么被生产出来的**：谁做、怎么做、谁验收、什么算合格。
> 目标：682 页课件 → 可离线阅读、可自评、可复习的 App 内容，且**事实可追溯、质量可复核**。

---

## 0. 铁律

1. **只依据课件**：任何结论都必须能在课件原文里找到出处，交付时标注页码（`p12`）。课件没讲的，最多写一句"（课件未涉及）"，**不许自己发挥**。
2. **不偷懒、不压缩**：要求逐页分析就必须逐页；过渡页可写得短，但**不能跳过**。
3. **两人独立产出 + 第三人复核**：同一份内容至少由两个智能体各自独立完成，再由第三个智能体比对、挑错、定稿。**单一来源的内容一律不采信**。
4. **形式服从 App**：一切产物必须符合 `docs/CONTENT-SPEC.md`（Mermaid、公式、表格、自评单元规则）。

---

## 1. 角色

| 角色 | 职责 | 产出 |
|---|---|---|
| **Lead（我）** | 拆任务、给上下文、合并、跑构建/校验、对用户交付 | 最终 HTML、构建日志、验收报告 |
| **Producer A** | 按模板独立写一份 | `draft/A/<deck>_<页段>.md` |
| **Producer B** | 拿到**同样的输入**、独立写一份（不参考 A） | `draft/B/<deck>_<页段>.md` |
| **Reviewer** | 逐段比对 A/B + 回查课件，出"差异清单 + 采信建议" | `review/<deck>_<页段>.md` |
| **Verifier（可选）** | 只做机器能查的：结构、id 唯一、公式、盒线字符、断链 | 构建/校验日志 |

> 为什么不用"1 人写 + 1 人校"：单人对课件的理解偏差会被校对者沿用；
> 双盲独立产出能暴露"两人理解不一致"的地方，而**不一致处往往就是最容易考/最容易错的地方**。

---

## 2. 任务拆分

- 以**课件为单位**（9 个），每个课件再按 **10–15 页**切成段，一段一个任务。
- 每个任务输入固定为：该段的逐页文本（`course/raw/<deck>.md` 的对应片段）+ 该段页码区间 + 本规范摘要。
- 单个任务产出上限约 3–5KB（太长会牺牲精度）；超出就再切。

---

## 3. 单页模板（Producer 必须逐页照写）

```markdown
### p12 · 「进程状态机」（原页标题）
**课件原文要点**
- （照抄/压缩课件里的 bullet，不改语义）

**把它讲成人话（0 基础版）**
- 一句话结论：……
- 打个比方：……（生活类比，帮助建立直觉）
- 为什么需要它：……（不这么做会出什么问题）
- 和上一页的关系：……（承上启下）

**易错点**
- ◆坑：……

**图示（可选）**
- 需要画图的，给出 Mermaid 源码（flowchart/stateDiagram），节点 ≤ 12

**课上原话/可疑处（可选）**
- 课件此处表述含糊 → 标注"待确认"，不要自行补全
```

> 讲解要求：「把我当傻子」= 不假设读者知道任何前置概念；每个术语第一次出现必须解释；
> 每段不超过 6 行（手机屏幕）；**禁止**"显然/众所周知/不难看出"这类词。

---

## 4. 每课件收尾（每个 deck 一份）

1. **考点清单**：分「核心考点（闭眼要会）」「一般考点」「易错点」三档，每条标注页码。
2. **随堂检测**：8–12 题，题型覆盖 选择/填空/简答；**每题必须有详细题解**（为什么对、其他选项为什么错）。
3. **一页速记卡**：全部公式 + 关键数字 + 判定规则，做成表格。
4. **自评单元**：按 `CONTENT-SPEC §5` 的规则落地（每题的标题能被规则命中）。

---

## 5. 复核流程（质量门）

Reviewer 对 A/B 两份稿逐段打分，输出表格：

| 段 | 事实一致性 | 完整性 | 可读性 | 差异点 | 采信建议 |
|---|---|---|---|---|---|
| p12 | ✅/⚠️/❌ | … | … | A 说 X，B 说 Y，课件原文是 Z | 取 A 的第 2 段 + B 的类比 |

**判定标准**

- **事实一致性**：能否在课件对应页找到依据；数字、术语、因果方向必须一字不差。
- **完整性**：是否覆盖该页所有 bullet；是否漏了"坑"和"前提"。
- **可读性**：0 基础读者能否一次读懂；有没有跳跃。
- 出现 ❌ 的段，**必须由 Lead 重新写**，不得直接采信任一份。

---

## 7. 验收（Lead 每次合稿必跑）

```bash
node scripts/build.mjs     # 公式数/mermaid 数/纯文本块数是否合理
node scripts/verify.mjs    # 必须全绿（盒线字符为 0、公式基线、id 唯一…）
npm test
```

外加**人工抽检**：随机 3 页，与课件 PDF 逐条对照（我或 Reviewer 做，并在交付里写明抽检页码）。

---

## 8. 禁止事项

- 编造课件没有的定义、数字、例子
- 用"大约/可能"掩盖不确定；不确定就标"待确认"并给页码
- 把课件图用字符画重画（必须 Mermaid）
- 为了凑字数重复同一句话
- 单份稿直接定稿（跳过双人复核）
