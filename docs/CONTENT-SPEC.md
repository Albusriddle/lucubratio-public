# 内容生产规范（Content Spec）· Lucubratio App

> 本规范以 Apache-2.0 发布（见仓库根 LICENSE）；按本规范生成的内容版权归内容作者。

> 本文件是**写内容的人/智能体必须遵守的合同**。凡不符合的产物，构建会失败或观感崩坏。
> 适用：`content/os/*.html`（内容源）与 `content/diagrams/*.html`（图表源）。

---

## 0. 一句话总结

写**自包含的 HTML 片段**，用 `<h2>/<h3>` 分节并给 `id`，公式写成 `<code>` 纯文本或 `\(LaTeX\)`，
图**只用 Mermaid**（禁止字符画），自评单元按第 5 节的规则落地，其它交给构建期自动处理。

---

## 1. 文件与命名

| 项 | 规则 |
|---|---|
| 路径 | `content/os/NN_标题.html`（`NN` 两位数，决定首页排序与 `cid`） |
| 编码 | UTF-8，**LF 换行**（Windows 下也别写 CRLF） |
| 自包含 | 不引用任何外部图片/CSS/JS/CDN；样式可写在文件内 `<style>`（沿用现有页面的 `:root` 变量） |
| 不允许 | `<img src="http…">`、`<iframe>`、`<script>`（除 Mermaid 的 `text/plain` 外壳） |

`cid` = `os-` + 文件名前两位，例如 `content/os/12_第二章.html` → `os-12`。图表文件与自评规则都按 cid 关联。

---

## 2. 标题与锚点（必需）

```html
<h2 id="2.1-进程是什么">2.1 进程是什么</h2>
<h3 id="2.1.1-为什么需要抽象">2.1.1 为什么需要抽象</h3>
```

- 每页**至少 1 个 `<h2>`**；`<h3>` 可选但推荐（抽屉目录、搜索结果都按 h2/h3 切节）。
- `id` 必须：**页内唯一**、只含中文/字母/数字/`.`/`-`，不要空格与引号。
- 正文段落用 `<p>`，列表用 `<ul>/<li>`，强调用 `<strong>`（**不要**用 Markdown 的 `**`）。

---

## 3. 公式

| 写法 | 构建期行为 | 适用 |
|---|---|---|
| `<code>T周转 = T完成 − T到达</code>` | 自动识别 → LaTeX → MathML | 单行、结构简单的公式（推荐） |
| `\( \frac{a}{b} \)` | KaTeX 直接渲染成 MathML | 需要真 LaTeX 语法时 |
| `<pre>` 内**每行都是公式** | 整块转成公式块 | 公式清单 |

判定很保守：恰好 1 个 `=`、含 `= × ÷ Σ −`、不含代码形状（`; { } ( ) == += if for #`）。
**所以：`if (pid == 0)`、`fork()` 这类保持原样即可，不会被误转。**

## 4. 图：只用 Mermaid（**禁止字符画**）

### 4.1 写法

```html
<div class="mermaid"><script type="text/plain">flowchart TD
  A["进程 = 正在运行的程序"] --> B["有机器状态"]
</script></div>
```

- 源码必须放在 `<script type="text/plain">` 里（否则 `<br/>`、`-->` 会被 HTML 解析吃掉）。
- 只有含 `.mermaid` 的页面才会加载 5.3MB 的 Mermaid 库，不要滥用。
- 换行照写，**首行顶格**。

### 4.2 选型

| 内容 | 用 |
|---|---|
| 流程 / 因果链 / 判定树 | `flowchart TD`（纵向优先，手机上好看） |
| 状态机（就绪/运行/阻塞…） | `stateDiagram-v2` |
| 时间线 / 调度顺序 | `flowchart LR` + 时间标注（**不要用 gantt**，毫秒轴会出重复刻度） |
| 纯数据对比 | 直接用表格（见 §6），不要硬画 |

### 4.3 硬性要求

- 节点文字短（**≤ 18 个汉字/行**），长句用 `<br/>` 断行；`wrappingWidth` 已配置为 280。
- 节点 id 用 `A/B/C…`；标签内不要用英文双引号，需要引号用「」。
- **禁止**：`┌─┐│└┘`、`|----|`、`▼` 这类字符画（构建期会报错：盒线字符必须为 0）。
- 一张图解决一个知识点；节点超过 12 个就考虑拆成两张。

## 5. 自评单元（错题 → FSRS 的唯一入口）

构建期**按页 cid** 查规则，命中才给标题打 `data-qid`；**规则没命中 = 该页没有自评单元**，
而且 `verify` 会直接失败（"自评标题与标记数不一致"）——所以新页必须配规则。

规则表在 `scripts/build.mjs` 的 `QUESTION_RULES`，**每页一条**：

```js
const QUESTION_RULES = {
  'os-01': { level: 3, test: /^检测\s*\d+/ },   // 命中「检测 1（10 分）…」这类 h3
  'os-02': { level: 3, test: /^检测\s*\d+/ },
  // 你的课程：加一条即可
  // 'os-99': { level: 3, test: /^检测\s*\d+/ },
};
```

| 本仓库现状 | 规则 | 说明 |
|---|---|---|
| `os-01`、`os-02`（两页 demo） | `检测 N` 命中 h3 | 默认配置 |
| 你新增的内容页 | **需要自己加一条** | cid 取自文件名前缀（`03_xxx.html` → `os-03`） |
| 串讲 / 速记 / 模拟卷等非题目页 | 不要配规则 | 配了却一个都没命中，构建会报错 |

> 新页忘了配规则时，`verify` 会打印：`→ 若这是新页面：在 scripts/build.mjs 的 QUESTION_RULES 里为 os-99 加一条 …`，
> 照抄那行即可（这是**唯一**需要改代码的地方，也是 ROADMAP 里「规则去硬编码」尚未完成的原因）。

**检测题的写法**见下一小节；统一用「解析」这个词（旧稿里的「题解」是同一概念，
但壳层只折叠以「解析」开头的引用块，写成别的不会被折叠）。

## 5.5 图片（课件原页）

纯图页/关键图页按下面写法嵌入，路径必须以 `/` 开头（WebViewAssetLoader 的站点根）：

```html
<figure class="slide-fig">
  <img src="/img/vcpu-1/p012.webp" alt="课件 p12：进程状态转换图" loading="lazy">
  <figcaption>课件 p12 原图（上下文的唯一权威依据）</figcaption>
</figure>
```

- 图片是**证据**，正文讲解仍要写清楚，不能让读者必须看图才能懂。
- 只放与本节直接相关的页；一张图解决一个问题。
- `verify` 会检查：站内图片必须真实存在、`href="#x"` 必须能找到对应 `id`（写错会构建失败）。
- 命名 `pNNN.webp` 与课件页码一一对应（三位数），换课件就换目录。**实际资产一律是 `.webp`**（用 `.png` 会 404）。

## 6. 表格与提示块

```html
<div class="table-wrap"><table>
  <thead><tr><th>指标</th><th>公式</th></tr></thead>
  <tbody><tr><td>周转时间</td><td><code>T周转 = T完成 − T到达</code></td></tr></tbody>
</table></div>
```

- **必须**套 `.table-wrap`（窄屏才能横滑），否则表格会被压变形。
- 提示/引用用 `<blockquote>`；"坑"用 `◆坑：` 开头（与现有页面一致，便于搜索）。

## 7. 手机端硬性限制（写之前先读）

| 限制 | 具体要求 |
|---|---|
| 字号 | 正文 16px 起；不要出现 `<small>`、不要用 `px` 硬写字号（用相对值或不管，壳层会统一） |
| 行宽 | 单段不要超过 6 行；长段拆段 |
| 表格列数 | ≤ 5 列；超过就改成"字段：值"的列表 |
| 代码块 | 一行 ≤ 60 字符，超了手动折行 |
| 公式 | 一行只放一条；两条并排会被拆（构建期会拆，但作者最好自己分行） |
| 图片 | **允许**（课件纯图页作为"事实佐证"嵌入）。放在 `web/img/<deck>/pNNN.webp`，引用写 `/img/<deck>/pNNN.webp`；单张 ≤ 200KB，宽度 1000px。当前 303 张在用，另有 39 张备用图放在 `content/img-unused/`（不进 APK） |

## 8. 质量红线（会被 CI 拦下）

1. 盒线字符（`│┌┐└┘├┤┬┴┼`）出现 → **构建失败**（verify 门禁）
2. 公式数量掉下基线（< 450）→ 失败（说明内容被改坏了）
3. `<pre>` 里出现未转义的 `<` `>` → 结构会被吃坏
4. `id` 重复 / 缺失 → 抽屉与搜索结果跳错位置
5. `file://`、外链、外站脚本 → 禁止

```bash
cd D:/std/study-app

node scripts/verify.mjs    # 必须全绿
npm test                   # 21 项纯函数测试
```

### Mermaid 写法（硬性，否则 `verify` 会拒）

**必须**写成"同一行开头"的形式：

```html
<div class="mermaid"><script type="text/plain">flowchart TD
  A["起点"] --> B["中间"]
  B --> C["结果"]
</script></div>
```

反例（会被 `node scripts/verify.mjs` 判为非法）：

```html
<!-- ❌ div 与 script 分行 -->
<div class="mermaid">
<script type="text/plain">flowchart TD
```

规则小结：

| 项 | 要求 |
|---|---|
| 起始 | `<div class="mermaid"><script type="text/plain">flowchart TD` 必须在**同一行** |
| 结束 | `</script></div>`（中间不要插 `</div>`） |
| 节点文字 | 一律用双引号包裹，如 `A["页表项"]` |
| 字符画 | **禁止**（盒线字符 `─│┌` 与方块 `█▀` 都会被打回），一律改用 Mermaid |
| 脚本 | 全篇只允许 `<script type="text/plain">` 这一种 `<script>`（Mermaid 源码容器）；其它任何 `<script>` 都会被 `pack`/导入拒绝 |

### 课件页截图

正文转述某页的图/表时，在该段之后写：

```html
<figure class="sa-ppt" data-ppt="42"></figure>
```

构建期替换为 `<img loading="lazy">` + 图注；宽度自动适配手机，点击可放大。

### 检测题（自评单元）约定

```html
<h3 id="检测 1">检测 1（10 分）题干……</h3>
<p>A. …　B. …　C. …　D. …</p>
<blockquote><strong>解析</strong>：…（课件 p42）</blockquote>
```

| 项 | 要求 |
|---|---|
| 标题 | `检测 N（10 分）`——`QUESTION_RULES` 是**按页 cid 配置**（每页一条 + 标题正则），`N` 只用于生成锚点 |
| 题干长度 | ≤80 字（过长说明把整段塞进了题干） |
| 选项 | A–D 四个都要有，**错因各不相同**（概念混淆 / 方向反 / 条件错 / 算错） |
| 解析 | 必须标页码；每个干扰项都要被点破 |
| 引注写法 | 依据 PPT 页：`（课件 p42）`；依据教材页：`（教材 p251）`。若某题依据的是教材而非 PPT（PPT 未展开），在该题组前用一句话说明来源 |
| 解析的呈现 | **查看器默认折叠**，点「查看解析」才展开，自评后自动展开。所以解析必须单独成一个 `<blockquote>`，紧跟第 4 个选项；不要在题干/选项里写答案，也不要加 `<details>` 或自造按钮 |
| 解析首句 | 必须以「X 对。」开头（明确答案），再逐项点破干扰项 |
| 一页题量 | 3–8 道（整门课按 `AGENTS-SPEC` 的配额表） |

写好之后可以先自检：`node tools/self-check-quizzes.mjs <页面.html>`。
