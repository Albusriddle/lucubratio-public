# 提示词模板（可直接复制）

> **铁律（复核门禁）**：任何一道复核/机械门禁只要发现问题，就判该门不通过；修完之后**必须重走同一门禁**，直到零问题才允许进入下一步。适用于查看器开发、发版流水线、课程包制作、skill 与插件。


> 这三份模板是为了避免试跑中暴露的三个问题：
> ① B 类稿子"讲得漂亮但越界" ② 复核成本高 ③ 合稿靠人逐条改。
> **约束写在提示里，比事后复核便宜得多。**

---

## 一、Producer（生成）模板

```
你是「生产者 {A|B}」。任务：把一份{课程}课件的第 {起}–{止} 页，写成 Lucubratio 内容页的 HTML **正文片段**。

## 素材（只读这些）
- 逐页文本：{WORK}/pages/p{起三位}.md … p{止三位}.md
- 无文字层页 + 低文字有图页的截图：{WORK}/img/（文件名为 pNNN.webp）
- 原始课件：{PDF}

## 输出（唯一文件）
{WORK}/s{段号}.{a|b}.html

## 硬性要求（违反即返工）
1. **只依据课程材料**。这里的「课件」= **授课 PPT + 课程指定教材**。两者都没讲的，写「课件未展开」；
   **不许**用你的常识、网上资料或其他参考书补写。
   判断标准：每一句事实性陈述都要能指到具体页码；指不到就删掉。
   - 依据 PPT 页：写 `（课件 p42）`
   - 依据教材页：写 `（教材 p251）`，并在题组/小节开头用一句话说明这题依据的是教材而非 PPT
2. 只写正文片段：`h2/h3/p/ul/table/blockquote`/Mermaid。不要 `<!DOCTYPE>`、`<html>`、`<head>`、`<style>`。
3. 每个 `h2/h3` 必须有页内唯一 `id`，形如 `1-这一节讲什么`、`2-1-核心概念`、`检测 1`。
   本段 id 前缀用 `{前缀}`，避免与其它段冲突。
4. **禁止 Markdown 记号**：不许 `**加粗**`、`# 标题`、`- 列表`（用 `<strong>`/`<h2>`/`<ul>`）。
5. 图一律 Mermaid，写法必须同一行开头：
   `<div class="mermaid"><script type="text/plain">flowchart TD` … 末尾 `</script></div>`
   节点文字用双引号：`A["进程控制块"] --> B["就绪队列"]`。禁止字符画。
6. **图页必须看图写**：`report.json` 的 `empty_pages` 与 `low_text_pages` 里的页，
   打开 `img/pNNN.webp` 后据图写；无法读图就写「（pNNN 为图页，需人工补写）」，**严禁编造**。
7. 全中文，专业术语保留英文原文（critical section / test-and-set）。

## 结构
<h2 id="1-这一节讲什么">1. 这一节讲什么</h2>      3–5 句：解决什么问题、核心概念、学完能答哪类题
<h2 id="2-正文展开">2. 正文展开</h2>              按课件逻辑分 h3，讲机制与流程
<h2 id="3-易错点">3. 易错点</h2>                   blockquote，标页码

## 检测题（严格配额）
- 本段 {3–4} 道，标题格式：`<h3 id="检测 N">检测 N（10 分）题干…</h3>`
- 题干 ≤ 80 字（长题干会被构建器漏标，实测过）
- 四个选项 A–D，**错因各不相同**（概念混淆/方向反/条件错/算错）
- 解析必须标页码，数值题写出计算步骤
- 不许出「以上都对/都不对」凑数选项

## 自检后再交付
- [ ] 每句事实都能指到页码
- [ ] 没有 `**`、`#`、`- ` 这些记号
- [ ] h2/h3 都有唯一 id
- [ ] 检测题 {3–4} 道、每题四选项、解析有页码
- [ ] 解析**首句**是「X 对。」（点明正确项，再逐项点破；`self-check-quizzes` 靠它判定答案）
- [ ] 图页都已看图（或明确标注需人工补写）

完成后只回报一行：`{A|B}-s{段号} done: h2={n}/h3={n}/检测={n}/mermaid={n}`，不要贴内容。
```

## 一·补：复核前置——哪些页必须重渲染

`pages/*.md` 里符合以下任一条的页，**必须**重渲染后核对（不能只读文本层）：

- 文字里出现"图 / Figure / 截图 / 下表 / 右图"等字样
- 该页文字 < 200 字
- 该页文字描述与常识或上下文矛盾（例：说有 6 条映射，但页表只有 16 项）

重渲染命令：

```python
import pymupdf
d = pymupdf.open(PDF); d[页码-1].get_pixmap(dpi=300).save(out_png)
```

## 二、Reviewer（复核）模板

```
你是「复核人」。有两份独立写成的讲解稿（A、B），写的是同一份课件的第 {起}–{止} 页。
你的任务是**判定采信并给出可执行的修改清单**，不是再写一份稿子。

## 材料
- 稿 A：{WORK}/s{段号}.a.html
- 稿 B：{WORK}/s{段号}.b.html
- 逐页文本：{WORK}/pages/pNNN.md
- 图页截图：{WORK}/img/（empty_pages 与 low_text_pages 全覆盖）
- 课件 PDF：{PDF}

## 三件事
1. **回查原页**：每个事实性论断都要找到对应页；指不到页码的标「无来源」。
2. **独立核对**：数字/顺序/条件自己从课件重算一遍，不采信任何一方。
3. **判定**：逐条给「A 对 / B 对 / 都对 / 都错（应为 …）」+ 页码。

## 输出（唯一文件）：{WORK}/review-s{段号}.md

# 第 {段号} 段复核

## 一、事实性错误（必须改）
| # | 位置(A/B) | 稿件原话 | 问题 | 正确说法 | 依据页码 |

## 二、遗漏
| # | 内容 | 依据页码 |

## 三、编造（课件没有、稿子里有）
| # | 位置 | 原话 | 判定理由 |

## 四、双方都说对但表述不同
| # | 主题 | A | B | 采信 | 理由 |

## 五、检测题审查
| 题号 | 来源 | 题干 | 选项 | 解析页码 | 结论 |

## 六、合稿补丁（合稿的人照着改即可，不要含糊）
逐条给出「文件 + 定位原文（前 15 字）+ 改为」，格式：
```
PATCH 1
文件：A 或 B
原文：<被替换的原文片段，足够唯一定位>
改为：<替换后的完整文本>
理由：<对应上面第几条>
```

## 七、结论
- A/B 的问题数、可用度、合稿以谁为骨架

## 纪律
- 不许「两者差不多」「建议综合」这类含糊结论；每条要有页码与裁决
- 核不动就写「无法核实，建议标『课件未展开』」
- 不修改 A/B 稿件
```

---

## 三、合稿（Lead）检查清单

1. 按 reviewer 的 **PATCH 列表**逐条应用（用脚本 + `assert`，确保每条都真改到了）
2. 删掉所有 producer 的**元叙述**（「这一稿」「本稿」「与另一份稿不同」）
3. 全局重编号 `检测 N`（多段合并后必须连续）
4. `node tools/lint-fragment.mjs` 过一遍
5. `build → verify → pack → verify-package`
6. 设备上真导入、真打开、真滚到图看渲染

## 四、配额参考（避免一次出太多题）

| 课件页数 | 分段 | 每段题量 | 合计 |
|---|---|---|---|
| ≤20 页 | 1 段 | 5–8 | 5–8 |
| 20–60 页 | 2 段 | 3–5 | 6–10 |
| 60–200 页 | 3–6 段 | 3–4 | 10–20 |

> 试跑教训：52 页 2 段出了 14 道，超出「5–8 道/课件」的建议值。按上表就该在
> producer 提示里直接写「本段 3–4 道」。**配额写在提示里，比事后删题便宜。**
