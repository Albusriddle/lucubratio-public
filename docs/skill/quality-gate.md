# 质量门：双盲生成 + 复核

这套规则来自一次真实的全量产出（9 个课件、682 页），**每一条都对应过真实事故**。

## 一、为什么双盲

单份生成必然有系统性偏差：模型会顺着一个错误理解一路写下去，且读起来自洽。

两份独立稿 + 一份复核，能把错误分成三类：

| 类型 | 表现 | 处理 |
|---|---|---|
| 事实错 | 与课件正文冲突 | 采信与课件一致的一方；两方都错则据课件重写 |
| 遗漏 | 课件讲了、稿子没写 | 补写，不删课件内容 |
| 编造 | 课件没有、稿子里有 | **整段删掉**，不保留"合理推测" |

## 二、reviewer 的三件事（缺一不可）

1. **回查原页**：每个事实性论断都要能指到 `p<页码>`；指不到就不能采信
2. **独立重算**：数值类（调度顺序、命中率、页表项数、地址位数）自己算一遍，与两稿比对
3. **判定采信**：逐条写「A 对 / B 对 / 都不对（应为 …）」，禁止"两者结合一下"这种含糊结论

reviewer 的输出是**决策**，不是又一份稿子。没有决策的 review 视为没做。

## 三、合稿规则

| 情形 | 做法 |
|---|---|
| A、B 都对且一致 | 取表述更清楚的一版 |
| A 对 B 错 | 取 A，且把 B 的错处在报告里记一笔 |
| 都错 | 据课件重写，并记入报告的"高风险点" |
| 都对但侧重不同 | 合并，注意别写出重复段落 |
| 课件本身含糊 | 写「课件未展开」，并标页码让用户自己确认 |

## 四、出题的额外要求

- 每题的**错误选项**都要有明确的错因（概念混淆 / 方向反了 / 适用条件错 / 数值算错）
- 不允许「以上都对」「以上都不对」作为凑数选项
- 解析里标页码；数值题标出关键计算步骤

## 五、自查清单（合稿前逐项过）

- [ ] 每段的 reviewer 结论已落地（采信项数 + 重写项数）
- [ ] `report.json.empty_pages` 全部有对应内容且注明"据图"
- [ ] 所有 `h2/h3` 有唯一 `id`
- [ ] 没有 `**…**`、`# 标题` 这类 Markdown 残留
- [ ] Mermaid 块写法正确，且每个图都在正文里被提到（不是孤零零一张图）
- [ ] 检测题解析标了页码
- [ ] `verify` / `verify-package` 全绿
