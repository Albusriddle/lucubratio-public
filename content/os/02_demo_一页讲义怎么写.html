1. 一页的标准骨架

本流水线推荐的每页结构（也是本仓库样例页自己的写法）：

  1. 这一页在说什么：一两句话交代原文要点。
  2. 人话讲解：假设读者零基础，每个术语第一次出现就给定义。
  3. 打个比方：用生活里的东西类比，帮助建立直觉。
  4. 易错点：以「◆坑：」开头，写清最容易理解反的地方。
  5. （可选）一张图：流程、状态、时间线用 Mermaid。
为什么强调"人话"：一行公式摆在那里，读者要么看懂、要么跳过；而"它解决什么问题、不这么做会怎样"才是真正让人记住的东西。

2. 标题与锚点

每个 <h2> / <h3> 都要有页内唯一的 id，查看器的目录抽屉与检索都靠它跳转。

例如本页第一节的锚点就是 #1-一页的标准骨架，点目录可以直接跳过来。

3. 图：用 Mermaid，不要贴字符画

字符画在手机上必然错位（没有中文等宽字体），所以流程图请写成 Mermaid：

查看器会在图表进入视口时才加载渲染库，所以偶尔放几张不会拖慢首屏。

4. 自评单元：错题驱动复习的入口

标题形如「检测 1（10 分）」的 <h3>，会在运行时自动获得「不会 / 模糊 / 会」三个按钮；标记为「不会」的会进入 FSRS 复习队列。

哪些标题算"一个自评单元"由 scripts/build.mjs 的 QUESTION_RULES 决定——这就是你可以自定义的地方（未来会改成由 manifest 声明）。

5. 随堂检测

检测 1（10 分）为什么本流水线要求用 Mermaid 而不是 ASCII 字符画？（　　）

A. 因为字符画文件更大 B. 因为手机端没有中文等宽字体，汉字与字母宽度不成整数比，字符画必然错位 C. 因为 Mermaid 渲染更快 D. 因为字符画不能缩放

题解：

  • A 错。体积不是主要考虑。
  • B 对。汉字宽度约为英文字母的 1.67 倍，而字符画假定"一个汉字 = 两个字母宽"，边框与竖线必然对不齐；换字号、换字体都救不回来。
  • C 错。Mermaid 反而要加载 5MB 的渲染库（还是懒加载）。
  • D 错。字符画也能缩放，只是缩放了依旧错位。

检测 2（10 分）想让某个标题成为"可自评单元"，需要满足什么？（　　）

A. 随便什么标题都行 B. 标题文本命中 QUESTION_RULES 里该页 cid 配置的正则 C. 标题里必须包含「题」字 D. 必须在页末单独列出来

题解：

  • A 错。不做启发式猜测，必须显式配置。
  • B 对。构建期按 cid 查规则，命中才给标题加一个 data-qid 属性（值是 cid#标题id），运行时据此插入自评条。
  • C 错。「题」字不是必要条件，正则怎么写都行（本仓库默认用「检测 N」）。
  • D 错。位置无关，只看标题文本。
